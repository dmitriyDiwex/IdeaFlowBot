# IdeaFlowBot

IdeaFlowBot - Telegram-бот для сети каналов формата "подслушано". Он принимает сообщения из ботов-предложек, дает модераторам Telegram-панель, хранит библиотеку паст, планирует публикации по слотам и фильтрует пасты по тегам для разных каналов.

README сначала описывает панель, потому что это основной рабочий интерфейс для модераторов. Блоки про VPS, Docker, базу и обслуживание находятся ниже отдельно.

## Панель Для Модераторов

Панель открывается в главном Telegram-боте командой:

```text
/panel
```

Также можно отправить `/start`. Если твой Telegram ID есть в доступах, бот покажет кнопки панели.

### Роли

В проекте есть две роли:

- `GENERAL_ADMIN` - главный админ. Видит всю панель, включая управление сабботами и модераторами.
- `MODERATORS` - модераторы. Видят рабочие разделы для сообщений, паст, каналов, тегов, слотов, scheduler/publisher и дополнительных функций, но не видят кнопки `Сабботы` и `Модераторы`.

Главный админ задается в `.env` через числовой Telegram ID:

```env
GENERAL_ADMIN=123456789
```

Модераторы задаются через `.env` или добавляются из панели главным админом:

```env
MODERATORS=123456789,987654321
```

### Главное Меню

В обычной панели есть такие кнопки:

| Кнопка | Для чего нужна |
| --- | --- |
| `Обновить входящие` | Вручную переносит новые сообщения из collector-таблиц в editorial submissions. Обычно importer делает это сам раз в минуту, но кнопка полезна для проверки сразу после запуска. |
| `Поступившие сообщения` | Показывает новые сообщения из предложек, которые ждут модерации. |
| `Все сообщения` | Показывает историю submissions, включая уже обработанные сообщения. |
| `Черновики на review` | Показывает готовые content items, которые ждут approve/reject перед публикацией. |
| `Пасты` | Библиотека готовых паст: просмотр, добавление, удаление и настройка тегов конкретной пасты. |
| `Признавашки` | Отдельная библиотека сообщений для каналов признавашек, подключение бота-копировщика и настройка пабликов со слотами. |
| `Каналы и слоты` | Каналы, расписание публикаций, параметры канала, рекламные окна, генерация и правила тегов паст для канала. |
| `Теги` | Справочник тегов, ключевые слова, включение/выключение тегов и массовые include/exclude правила для всех каналов. |
| `Мои каналы` | Ручная отправка одного сообщения в выбранный канал или сразу во все каналы, на которые подписан модератор. |
| `Запустить scheduler` | Вручную запускает планировщик, который подбирает контент под ближайшие слоты. |
| `Запустить publisher` | Вручную запускает публикацию запланированных постов, у которых уже пришло время. |
| `Дополнительные функции` | Выгрузка базы, статистики каналов, статистики администраторов и SQL -> CSV. |
| `Добавить исключения для рекламы` | Показывает и изменяет общий список ссылок, которые не должны создавать автоматическое часовое рекламное окно. |

У главного админа дополнительно есть:

| Кнопка | Для чего нужна |
| --- | --- |
| `Сабботы` | Добавление и удаление ботов-предложек. |
| `Модераторы` | Добавление и удаление модераторов по Telegram user ID. |

## Работа С Сообщениями Из Предложки

Сообщение пользователя сначала приходит в саббота, затем сохраняется в collector-таблицах. После этого `editorial-importer` или кнопка `Обновить входящие` переносит его в `submissions`.

Раздел `Поступившие сообщения` показывает новые сообщения по одному. На карточке сообщения есть действия:

| Кнопка | Что делает |
| --- | --- |
| `Approve` | Одобряет сообщение и создает из него content item для дальнейшей публикации. |
| `Publish now` | Пытается сразу отправить сообщение в публикационный pipeline без ожидания обычного слота. |
| `Save as paste` | Сохраняет текст сообщения как пасту в библиотеку. |
| `Hold` | Откладывает сообщение, чтобы не принимать решение сейчас. |
| `Анон` / `Не анон` | Переключает режим публикации автора: анонимно или не анонимно. |
| `Реклама` | Помечает/обрабатывает сообщение как рекламное обращение через отдельный сценарий. |
| `Ответить` | Позволяет модератору отправить ответ пользователю через бота. |
| `Ban user` | Блокирует пользователя, чтобы он больше не мог нормально отправлять сообщения через предложку. |
| `Reject` | Отклоняет сообщение. |
| `Удалить сообщение` | Удаляет запись сообщения из списка. |
| `Следующее сообщение` | Переходит к следующему сообщению в очереди. |
| `Назад в панель` | Возвращает в главное меню. |

Раздел `Все сообщения` похож на `Поступившие сообщения`, но показывает историю. Там удобно искать старые submissions, повторно смотреть текст, удалить запись или выполнить доступное действие, если сообщение еще можно модерировать.

## Черновики На Review

`Черновики на review` - это уже подготовленные content items. Они могут появиться после approve сообщения, генерации или других внутренних сценариев.

Доступные кнопки:

| Кнопка | Что делает |
| --- | --- |
| `Approve` | Одобряет черновик для дальнейшего планирования. |
| `Publish now` | Пытается опубликовать черновик сразу. |
| `Hold` | Возвращает черновик в ожидание. |
| `Reject` | Отклоняет черновик. |
| `Изменить` | Дает отредактировать текст черновика. |
| `Следующий черновик` | Открывает следующий черновик на review. |

## Пасты

Паста - это готовый текст из библиотеки, который бот может использовать для публикации по расписанию. Пасты нужны, чтобы каналы не зависели только от новых сообщений из предложки.

Пасту можно создать:

- из сообщения кнопкой `Save as paste`;
- вручную в разделе `Пасты` кнопкой `Добавить пасту`;
- из другого content item, если такой сценарий используется в панели.

При ручном добавлении можно отправить просто текст пасты или формат:

```text
Заголовок :: Текст пасты
```

В карточке пасты есть кнопки:

| Кнопка | Что делает |
| --- | --- |
| `Добавить пасту` | Создает новую пасту из текста, который отправит модератор. |
| `Удалить пасту` | Удаляет текущую пасту. |
| `Теги пасты` | Открывает управление тегами конкретной пасты. |
| `Следующая паста` | Показывает следующую пасту в библиотеке. |

## Признавашки

Раздел `Признавашки` использует отдельную библиотеку паст и одного общего бота-публикатора для всех пабликов признавашек. Обычные пасты подслушек с этой библиотекой не смешиваются. Для каждого паблика при необходимости подключается свой отдельный саббот-предложка, использующий ту же систему входящих сообщений и модерации, что и подслушки.

Первичная настройка выполняется главным администратором:

1. Открыть `Признавашки -> Подключить бота паст` и отправить токен отдельного Telegram-бота для хранения и публикации паст.
2. Нажать `Добавить чат для паст`, создать закрытую группу-хранилище, добавить этого бота администратором и отправить в группе выданную панелью команду `/connect_confessions CODE`.
3. Добавлять в эту группу готовые сообщения. После каждого текста, фото, видео, анимации, документа, голосового сообщения или стикера бот спросит `Добавить эту пасту в базу?`. Только кнопка `Да` создаёт активную пасту; кнопка `Нет` оставляет сообщение вне библиотеки.
4. Открыть `Признавашки -> Паблики -> Подключить паблик`, добавить того же бота администратором канала с правом публикации и отправить панели `@username` или numeric id канала.
5. Открыть карточку паблика и нажать `Подключить саббота-предложку`. Создать ещё одного бота, добавить его администратором паблика, затем отправить панели его token.
6. Добавить бота-предложку администратором в нужный чат модерации. Сообщения пользователей будут приходить туда с теми же кнопками и действиями, что и у подслушек.
7. Настроить слоты и параметры паблика. Используются те же ручные и автоматические слоты и те же профили настроек, что и для подслушек; отдельные профили признавашек создавать не нужно.

В момент слота scheduler сначала выбирает одобренное сообщение из предложки этого паблика. Только если подходящего одобренного контента нет, свободный слот заполняется доступной пастой признавашек. Для паст publisher вызывает Telegram `copyMessage` из группы-хранилища, поэтому исходные entities сообщения, включая custom emoji, и исходный стикер не пересобираются ботом. Бот паст должен оставаться участником группы-хранилища и администратором каждого паблика, а бот-предложка — администратором своего паблика и чата модерации.

В карточке паблика признавашек можно вручную поставить или удалить рекламное окно в том же формате, что и для обычных каналов. Общий саббот также отслеживает новые и отредактированные посты паблика: внешняя ссылка создаёт часовое рекламное окно от времени публикации, а ссылка на сам паблик игнорируется. Уже занятые слоты остаются запланированными и публикуются после окончания окна.

Для служебного общения в чате-хранилище начните текст или подпись к медиа со знака `/`. Такое сообщение бот проигнорирует и даже не покажет запрос подтверждения.

## Система Тегов

Теги используются прежде всего для паст. Они помогают отделять, например, пасты для технических вузов от паст для художественных вузов, а также временно включать сезонные подборки вроде `summer`.

У пасты могут быть:

- авто-теги - бот ставит их по ключевым словам;
- ручные теги - модератор ставит их сам;
- основной тег - главный тег пасты для cooldown-логики и более понятной карточки.

### Раздел `Теги`

В разделе `Теги` есть:

| Кнопка | Что делает |
| --- | --- |
| `Добавить тег` | Создает новый тег. Формат: `slug` или `slug :: Название`, например `summer :: Лето`. |
| `Массовые правила паст` | Открывает include/exclude правила сразу для всех каналов. |
| Карточка конкретного тега | Открывает управление выбранным тегом. |

В карточке тега:

| Кнопка | Что делает |
| --- | --- |
| `Добавить ключевые слова` | Добавляет слова, по которым бот будет автоматически ставить этот тег пастам. Можно писать через запятую: `лето, каникулы, июль`. |
| `Ключевые слова` | Показывает ключевые слова тега и дает удалить лишние. |
| `Выключить тег` / `Включить тег` | Отключает или включает тег. Выключенный тег не должен участвовать в обычной работе. |

### Теги Конкретной Пасты

В `Пасты -> Теги пасты` есть:

| Кнопка | Что делает |
| --- | --- |
| `Добавить ручной тег` | Ставит пасте тег вручную по slug. |
| `Убрать ручной тег` | Убирает ручной тег с пасты. |
| `Сделать тег основным` | Делает выбранный тег основным для пасты. |
| `Пересчитать авто-теги` | Заново прогоняет текст пасты по ключевым словам тегов. |

Ручной тег удобен, когда ключевых слов недостаточно или пасту надо жестко отнести к категории.

### Include И Exclude Для Канала

У каждого канала можно настроить правила паст:

- include, в панели `обязательный тег` - канал берет только пасты с этим тегом;
- exclude, в панели `запрещённый тег` - канал не берет пасты с этим тегом.

Если include-список пуст, канал может брать любые пасты, кроме запрещенных. Если include есть, паста должна иметь хотя бы один обязательный тег. Exclude сильнее include: если паста одновременно подходит по include, но имеет запрещенный тег, она не будет выбрана.

Настройка находится здесь:

```text
Каналы и слоты -> нужный канал -> Теги паст
```

Кнопки:

| Кнопка | Что делает |
| --- | --- |
| `Добавить обязательный тег` | Добавляет include-тег для выбранного канала. Можно отправить несколько slug через запятую. |
| `Добавить запрещённый тег` | Добавляет exclude-тег для выбранного канала. |
| `Удалить обязательный тег` | Убирает include-тег у выбранного канала. |
| `Удалить запрещённый тег` | Убирает exclude-тег у выбранного канала. |

Примеры:

```text
art
tech, programming
summer
```

### Массовые Правила Для Всех Каналов

Если нужно быстро включить сезонную логику для всей сети, используется:

```text
Теги -> Массовые правила паст
```

Кнопки:

| Кнопка | Что делает |
| --- | --- |
| `Поставить Include для всех` | Все каналы начинают брать только пасты с указанным тегом. Можно задать срок действия. |
| `Убрать Include для всех` | Убирает глобальный include для указанного тега. |
| `Поставить Exclude для всех` | Все каналы перестают брать пасты с указанным тегом. Можно задать срок действия. |
| `Убрать Exclude для всех` | Убирает глобальный exclude для указанного тега. |

Форматы для временного правила:

```text
summer до 2026-08-31
summer 31.08.2026 23:59
summer until 2026-08-31
```

Можно отправить несколько тегов:

```text
summer, exam
```

Для remove-кнопок достаточно отправить slug тега или несколько slug через запятую.

## Каналы И Слоты

Раздел `Каналы и слоты` показывает подключенные каналы. Внутри карточки канала доступны:

| Кнопка | Что делает |
| --- | --- |
| Переключатель уведомлений | Включает или выключает уведомления по каналу. |
| Переключатель ленты модерации | Включает или выключает получение сообщений/модерационной ленты для канала. |
| `Поставить рекламное окно` | Создает временной промежуток, когда бот не должен публиковать обычный контент из-за рекламы. |
| `Удалить рекламное окно` | Удаляет ранее заданное рекламное окно. |
| `Сгенерировать посты` | Запускает генерацию черновиков для канала, если генерация включена в `.env`. |
| `Настройка слотов` | Открывает добавление, удаление и создание стандартных слотов публикаций. |
| `Изменение параметров` | Позволяет менять настройки канала одной строкой. |
| `Теги паст` | Открывает include/exclude правила паст для этого канала. |

Саббот также автоматически отслеживает новые и отредактированные сообщения своего канала. Если в тексте, подписи или inline-кнопке есть внешняя ссылка, а не ссылка на сам канал, он создаёт рекламное окно на один час от времени публикации сообщения. Окно записывается в общий editorial-слой, поэтому учитывается как legacy-отложкой, так и новым publisher.

### Слоты

В `Настройка слотов` есть:

| Кнопка | Что делает |
| --- | --- |
| `Добавить слот` | Добавляет одно или несколько времен публикации. |
| `Удалить слоты` | Удаляет указанные времена публикации. |
| `Создать стандартные слоты` | Создает дефолтный набор слотов для канала. |

Форматы:

```text
12:00 15:00 16:00
all 10:00 15:00
0 09:30 18:00
0,2,4 18:00 21:00
```

Где `0` - понедельник, `6` - воскресенье.

### Рекламные Окна

Формат:

```text
<день месяца> <с HH:MM> <до HH:MM>
```

Пример:

```text
21 15:00 18:00
```

Такой интервал нужен, чтобы обычные автопубликации не мешали рекламе.

### Параметры Канала

Кнопка `Изменение параметров` просит отправить одну строку:

```text
<параметр> <значение>
```

Примеры:

```text
same_tag_cooldown_hours 24
allow_pastes false
max_posts_per_day 6
```

Доступные параметры:

| Параметр | Что означает |
| --- | --- |
| `title` | Название канала внутри панели. |
| `short_code` | Короткий код канала. |
| `is_active` | Активен ли канал. |
| `timezone` | Таймзона канала. |
| `min_gap_minutes` | Минимальный промежуток между публикациями. |
| `slot_jitter_minutes` | Допустимый сдвиг времени слота. |
| `max_posts_per_day` | Максимум постов в день. |
| `max_generated_per_day` | Максимум generated-контента в день. |
| `max_paste_per_day` | Максимум паст в день. |
| `same_tag_cooldown_hours` | Сколько часов не повторять один основной тег. |
| `same_template_cooldown_hours` | Сколько часов не повторять один шаблон. |
| `same_paste_cooldown_days` | Сколько дней не повторять одну и ту же пасту. |
| `min_ready_queue` | Минимальный желаемый запас готового контента. |
| `prefer_real_ratio` | Приоритет реальных сообщений относительно паст/генерации. |
| `allow_generated` | Разрешить generated-контент. |
| `allow_pastes` | Разрешить пасты. |

Для булевых значений можно использовать `true/false`, `yes/no`, `on/off`, `да/нет`.

## Мои Каналы

`Мои каналы` нужен для ручной публикации текста. Панель показывает каналы, на которые у модератора включена модерационная лента, и кнопку для отправки во все такие каналы.

Рабочий сценарий:

1. Нажать `Мои каналы`.
2. Выбрать конкретный канал или `Все мои каналы`.
3. Отправить текст одним сообщением.
4. Бот попробует опубликовать этот текст в выбранные каналы и пришлет результат.

## Сабботы

Этот раздел видит только главный админ.

Саббот - отдельный Telegram-бот, который принимает сообщения для конкретной предложки. Обычно схема такая:

```text
1 саббот = 1 предложка = 1 канал подслушки
```

Добавление:

```text
Сабботы -> Добавить саббота
```

Бот попросит строку:

```text
<api_token_саббота> @channel_username
```

После добавления бот привязывает саббота к каналу. Если у канала уже была история публикаций, панель может предложить импорт истории канала.

Удаление:

```text
Сабботы -> Удалить @username -> Да
```

## Дополнительные Функции

Раздел `Дополнительные функции` содержит:

| Кнопка | Что делает |

| `SQL -> CSV` | Позволяет получить CSV-результат для SQL-запроса. Использовать аккуратно, потому что это инструмент для технической диагностики. |

Кнопка `Добавить исключения для рекламы` находится в главной панели сразу после `Дополнительных функций`. Внутри можно добавить ссылку, удалить её по тому же адресу или вернуться в панель. Текущий ручной список показывается на этом же экране. Варианты `http/https`, префикс `www` и завершающий `/` при сравнении нормализуются. Исключение работает как безопасный URL-префикс: например, `https://ya.cc` исключает сам домен, его параметры и любые вложенные пути, но не похожие домены вроде `ya.cc.evil.example`. Исключение с путём, например `example.com/offer`, также распространяется на параметры и вложенные страницы этого пути, но не на `example.com/offering`.

Исключение действует на обычные сабботы и на паблики признавашек. Если в посте есть хотя бы одна ссылка из ручного списка исключений, часовое рекламное окно для всего поста не создаётся, даже когда рядом присутствуют другие внешние ссылки. Собственные ссылки каналов из подписей исключаются автоматически и в ручной список не входят.

Для оплаты модерации используется `moderation_cases`: на одну предложку или медиагруппу существует не более одной итоговой строки. Повторное нажатие той же кнопки не меняет администратора и не увеличивает счётчик. Смена решения обновляет существующую строку, а отмена помечает её исключённой из статистики. История таких переходов сохраняется отдельно в `moderation_case_events`.

## Scheduler И Publisher

В панели есть две ручные кнопки:

- `Запустить scheduler` - подобрать контент под слоты и создать запланированные публикации;
- `Запустить publisher` - опубликовать то, что уже запланировано и готово по времени.

На сервере эти процессы можно держать отдельными контейнерами `editorial-scheduler` и `editorial-publisher`, но ручные кнопки полезны при тестах и после изменения настроек.

Временная недоступность Telegram не удаляет запланированный пост и не переводит его в окончательную ошибку. `publication_log` остаётся в статусе `scheduled`, получает `retry_after` и повторяется с увеличивающейся паузой. Один Telegram-запрос ограничен по общему времени, а после первой транспортной ошибки текущий проход publisher останавливается, чтобы не создавать шторм повторных запросов. Легаси-отложки аналогично остаются в `delayed_posts` до успешной отправки.

Параметры устойчивости:

- `TELEGRAM_REQUEST_TIMEOUT_SECONDS` — максимальная длительность одной Telegram-операции, по умолчанию 15 секунд;
- `TELEGRAM_RETRY_DELAY_SECONDS` — пауза перед повтором легаси-публикации, по умолчанию 60 секунд;
- `EDITORIAL_PUBLISHER_RETRY_BASE_SECONDS` — начальная пауза нового publisher, по умолчанию 60 секунд;
- `EDITORIAL_PUBLISHER_RETRY_MAX_SECONDS` — максимальная пауза между попытками, по умолчанию 900 секунд.

## Типичный Рабочий День Модератора

1. Открыть `/panel`.
2. Нажать `Обновить входящие`, если нужно сразу подтянуть новые сообщения.
3. Зайти в `Поступившие сообщения`.
4. Для нормальных сообщений нажимать `Approve` или `Publish now`.
5. Хорошие универсальные тексты сохранять через `Save as paste`.
6. Спорные сообщения отправлять в `Hold`, плохие в `Reject`.
7. Для паст проверять `Теги пасты`, если текст явно относится к конкретной теме.
8. Если нужно сезонное ограничение, использовать `Теги -> Массовые правила паст`.

## Как Сейчас Устроен Проект

В проекте есть два логических слоя, но при обычном Docker-запуске они работают с одной PostgreSQL-базой:

- collector layer - главный бот и сабботы, которые принимают сообщения, хранят технические данные ботов, админов, пользователей, отложенных постов и входящих сообщений;
- editorial layer - moderation, submissions, content items, пасты, теги, слоты, scheduler, publisher, история публикаций и генерация;
- Telegram-панель - основной интерфейс управления прямо в главном боте.

Рабочий поток:

```text
пользователь -> бот-предложка -> collector tables -> editorial-importer -> submissions -> review -> schedule -> publish
```

Названия `legacy`, `core_database` и команда `import-legacy` в коде не означают, что проект сейчас обязан работать на старой SQLite-базе. Это совместимый collector-слой и перенос данных из collector-таблиц в editorial-таблицы.

SQLite используется только в двух случаях:

- как fallback, если не задан `EDITORIAL_POSTGRES_DSN` или `LEGACY_DATABASE_URL`;
- как источник одноразовой миграции старого файла `data/bot_network_db.db`, если он есть и PostgreSQL еще пустой.

На новом VPS с Docker основная рабочая база - PostgreSQL.

## Запуск На VPS С Чистой Базой

Этот блок нужен владельцу сервера, а не обычным модераторам.

### 1. Клонировать Репозиторий

```bash
git clone https://github.com/DmitryVlasov30/IdeaFlowBot.git IdeaFlowBot
cd IdeaFlowBot
```

Если хочешь именно чистую базу на новом сервере, не копируй туда старую папку `data` и старые SQL-дампы. Docker сам создаст новый volume `postgres_data`.

### 2. Создать `.env`

```bash
cp .env.example .env
nano .env
```

Минимальный пример:

```env
BOT_API_TOKEN=токен_главного_бота
GENERAL_ADMIN=твой_telegram_id
MODERATORS=твой_telegram_id

POSTGRES_DB=ideaflow_editorial
POSTGRES_USER=postgres
POSTGRES_PASSWORD=сложный_пароль_базы
EDITORIAL_POSTGRES_DSN=postgresql+asyncpg://postgres:сложный_пароль_базы@postgres:5432/ideaflow_editorial

EDITORIAL_REDIS_DSN=redis://redis:6379/0
EDITORIAL_API_HOST=0.0.0.0
EDITORIAL_API_PORT=8080
EDITORIAL_LOG_LEVEL=INFO

EDITORIAL_GENERATION_ENABLED=false
OPENROUTER_API_KEY=

SUP_BOT_LIMIT=700
MAX_SUBBOTS=150
TELEGRAM_CONNECTIONS_PER_BOT=4
TELEGRAM_CONNECTION_OVERHEAD=50
PUBLICATION_SIGNATURE_SKIP_IF_ADMIN_BOT_USERNAME=
```

Важно: пароль в `POSTGRES_PASSWORD` и пароль внутри `EDITORIAL_POSTGRES_DSN` должны совпадать.

Если у тебя 150 каналов, нормальная стартовая настройка:

```env
MAX_SUBBOTS=150
TELEGRAM_CONNECTIONS_PER_BOT=4
TELEGRAM_CONNECTION_OVERHEAD=50
SUP_BOT_LIMIT=700
```

`TELEGRAM_CONNECTIONS_PER_BOT=4` не означает четыре канала на одного саббота. Это запас HTTP-соединений Telegram-клиента на одного работающего бота. Один саббот по-прежнему обычно равен одной предложке и одному каналу.

### 3. Запустить Docker

```bash
docker compose up -d --build collector-bot editorial-api editorial-importer
```

Проверка:

```bash
docker compose ps
```

Обычно должны быть `Up` или `healthy` у:

- `postgres`
- `redis`
- `collector-bot`
- `editorial-api`
- `editorial-importer`

`editorial-migrate` после успешных миграций обычно будет `Exited`, это нормально.

Когда каналы, слоты и правила уже настроены, можно поднять фоновые auto-slots/scheduler/publisher:

```bash
docker compose up -d editorial-auto-slots editorial-scheduler editorial-publisher
```

### 4. Если Порт 8080 Занят

Ошибка вида `failed to bind host port 0.0.0.0:8080` означает, что порт 8080 уже занят другим процессом или контейнером.

В `docker-compose.yml` можно поменять внешний порт:

```yaml
ports:
  - "8081:8080"
```

После этого:

```bash
docker compose up -d editorial-api
```

## CLI Команды

Команды выполняются внутри контейнера приложения:

```bash
docker compose run --rm collector-bot python -m src.editorial.cli import-legacy
docker compose run --rm collector-bot python -m src.editorial.cli schedule
docker compose run --rm collector-bot python -m src.editorial.cli publish
docker compose run --rm collector-bot python -m src.editorial.cli generate --channel-id 1
```

Что делают команды:

- `import-legacy` - переносит новые collector-сообщения в editorial submissions;
- `schedule` - подбирает контент под расписание;
- `publish` - публикует уже запланированные посты;
- `generate` - генерирует черновики, если включена генерация.

## Генерация

Генерация выключена по умолчанию:

```env
EDITORIAL_GENERATION_ENABLED=false
OPENROUTER_API_KEY=
```

Чтобы включить, нужно задать ключ OpenRouter и параметры модели в `.env`. После этого кнопка `Сгенерировать посты` в карточке канала сможет создавать черновики, которые затем проходят review.
